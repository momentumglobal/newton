Frequently Asked Questions

How do I sign in?
Click "Sign in with Microsoft" on the Newton login page and authenticate with your Momentum Global Microsoft account. No separate password is required.
Why can't I see all pages in the navigation?
The pages you see depend on your assigned role. Talent Partners see project-level pages; Delivery Managers see the same plus additional detail panels; Leadership sees Company Dashboard; Admins see everything including the Config Panel.
I can't see my project — what do I do?
Your project access is controlled by your user assignment in the Config Panel. Contact your Admin to ensure you've been assigned to the correct project.
Why are some fields showing "—"?
A dash means the data hasn't been entered yet for that record. Fields like Talent Partner, Target Hire Date, and Budget are optional — they'll show "—" until populated.
How often does the data update?
Newton reads directly from SharePoint Lists via the Microsoft Graph API. Data updates in real time — refreshing the page will show the latest entries.
What does the KPI Period filter control?
The Month / Quarter / Year buttons on the dashboards filter the pipeline metrics (submissions, interviews, offers, hires) to activity recorded within that period of the current calendar year.
Who do I contact if something isn't working?
Raise it with your Newton Admin. For access issues, they can update user assignments directly in the Config Panel.

User Roles

Every Newton user is assigned one of four roles. Your role controls which pages you can see and whether you can add or edit data.

Admin

Full access to all pages and all projects. Can add, edit, and manage all records. Has access to the Config Panel for department and record management.

Delivery Manager

Access to Project Dashboard, Projects, Roles, Placements, Rejected Offers, and Weekly Activity for their assigned projects. Can add and edit records. Sees all Talent Partner activity within their projects.

Talent Partner

Access to Project Dashboard, Roles, Weekly Activity, Placements, and Rejected Offers scoped to their assigned project and their own activity. Can add and edit records.

Leadership

Read-only access to Company Dashboard. Provides a cross-project view of open roles, pipeline metrics, and Talent Partner activity. Cannot add or edit records.

Exporting to PDF

Pages with an ⎙ Export PDF button can be saved as a PDF document. Click the button to open your browser's print dialog, then configure it as follows before saving:

Destination

Set to Save as PDF. This saves the output as a file rather than sending it to a physical printer.

Options

Under the Options section, ensure Headers and footers is unticked and Background graphics is ticked. Background graphics must be enabled for the branded header block to print correctly.

These settings are not saved by the browser between sessions — you will need to set them each time you export.

Most Newton exports are landscape. Briefing Packs are the one exception and export in portrait — you do not need to change the orientation yourself.

Command Bar

Admin Delivery Manager Talent Partner Leadership

Press ⌘K (Mac) or Ctrl+K (Windows) anywhere in Reporting, People, Sales or Command Centre to open the Command Bar — a search overlay covering every page you have access to across all of Newton, not just your current module. Use the arrow keys and Enter to select a result, or Escape to close.

Finding a page

Start typing and matching pages appear immediately, ranked by how closely they match. Picking a page outside your current module takes you straight there.

Finding a role, project or person

Keep typing (2+ characters) and matching Roles, Projects and People appear alongside the page results, each labelled with its type. Selecting one opens that record's edit form directly — no need to find it in a list first.

Acting on a role

Role results carry three quick actions — Log activity, Update stage, Add placement — so you can go straight from a search to the action you needed, pre-scoped to that role.

The Command Bar only searches data already loaded in your session — nothing is fetched as you type, so results appear instantly.

Company Dashboard

Admin Leadership

A cross-project rollup giving a company-wide view of recruitment health. Data is not filtered by project — it covers all active projects.

KPI Tiles

The top strip shows current Active Projects, Active Pipelines and Open Headcount. The second strip shows pipeline metrics for the selected period: Hires, Submission Conversion, IV to Offer Ratio, Offer Success, Average Days to Hire, and Hired On Time percentage. Use the Month / Quarter / Year buttons to change the period.

Open Headcount is the headcount still to hire on active pipelines — unfilled, not cancelled, and with an Open Date (headcount without an Open Date is planned, not yet active). Hires counts placements with an Offer Accepted Date in the period. Average Days to Hire is measured per hire, from the headcount's Open Date to the Offer Accepted Date (hires against a headcount with no Open Date are left out). Hired On Time compares each hire with its own headcount's Target Hire Date. Offer Success still uses the offers and hires logged in Weekly Activity.

Roles Open 30+ Days

Lists all active roles whose oldest open headcount has been open for 30 or more days, sorted by project. Filled and cancelled headcount don't count. The Days Open cell is flagged: ! for 30–44 days open, ⚠ for 45+ days open.

Activity by Talent Partner

Shows outreach, submissions, interviews, offers, and hires per Talent Partner per project for the selected period. Use the Period dropdown to change the date range.

Project Dashboard

Admin Delivery Manager Talent Partner

A detailed view of recruitment performance for a single project. Delivery Managers and Admins can switch between projects using the Project dropdown, grouped into Active and Archive sections (A–Z within each). Talent Partners see their assigned project only, scoped to their own activity.

KPI Tiles

Shows Active Pipelines, Open Headcount, Pipeline Backlog and Avg Days Open (current) and Hires to Date (all time), plus period metrics: Submission Conversion, IV to Offer Ratio, Offer Success, Average Days to Hire, and Hired On Time. Use Month / Quarter / Year to change the KPI period.

Open Headcount is the headcount still to hire on the project's active pipelines — unfilled, not cancelled, and with an Open Date (headcount without an Open Date is planned, not yet active). Hires to Date is the number of placements recorded against the project. Avg Days Open averages every open headcount that has an Open Date. Average Days to Hire and Hired On Time work per hire, as on the Company Dashboard.

Roles Open 30+ Days

Same table as the Company Dashboard, filtered to the selected project only. No Project column — Role, Talent Partner, Stage, and Days Open are shown.

Pipeline Activity

A breakdown of weekly activity by role for the selected period, including Outreach, Responses, Screened, Submitted, Interview stages, Offers, and Hires. A Totals row summarises across all roles.

Activity by Talent Partner (DM / Admin only)

Aggregates pipeline activity by Talent Partner for the selected period.

Offer Rejection Reasons (DM / Admin only)

Counts rejected offers by reason category for the period.

Upcoming Starters (DM / Admin only)

Lists placed candidates with a provisional start date in the future.

Actual Spend vs Budget (DM / Admin only)

Compares agreed salaries against budget, hire by hire: each placement adds its role's per-head budget and its agreed salary, so a role with three hires is budgeted three times. Placements without a salary (or on a role with no budget) are left out of both columns and counted in a note under the table.

Role Analytics (DM / Admin only)

A predictive analytics panel that appears below the core dashboard panels. For each active role it shows a Time-to-Fill prediction (the median total time to hire, in weeks with a ± band, based on past hires and currently open headcount in the same function and location — each hire and each open headcount counts separately — shown faded when there wasn't enough data for that location and it has been pooled across all locations for the function; hover it to see what it is based on) and a funnel conversion rate (submissions to hire). This panel always shows all-time data for each active role — it is not affected by the Period dropdown.

Use the Period dropdown to filter the detail panels independently from the KPI period buttons.

Projects

Admin Delivery Manager Talent Partner

Lists all projects you have access to, showing the customer name, status (Active / Transition / Completed), and start date. Admins and Delivery Managers can add new projects and edit existing ones using the buttons in the table.

Project status drives what appears in the Company Dashboard — only Active projects count toward the Active Projects KPI.

Roles

Admin Delivery Manager Talent Partner

A list of all roles across your accessible projects. A role is a pipeline for one role profile; each hire you are asked to make on it is a headcount. Each row shows the project, role title, location, stage, assigned Talent Partner, budget, Headcount and Days Open.

  • Headcount x/y — x open headcount out of y (open + filled). Cancelled headcount don't count. Hover the cell for the full breakdown, e.g. "2 open of 3 · 1 filled · 1 cancelled".
  • Days Open — days since the oldest open headcount's Open Date. Blank when no open headcount has an Open Date yet, and on the Backlog, Closed and Cancelled filters.

Filtering

Use the Project dropdown to filter by project — grouped into Active and Archive sections (A–Z within each). Use the stage filter buttons (Backlog / Active / Closed / Cancelled) to narrow by stage — Backlog covers both Backlog and On-hold roles, and Active means everything that is not Backlog, On-hold, Closed or Cancelled. Closed is the stage formerly called Hired: the pipeline has been filled and shut down.

The Show dropdown sets how many rows are drawn (25 / 50 / 100 / All, default 50). It only affects the display — nothing is re-fetched — and the line under the toolbar tells you what you are looking at. Roles has no date window on purpose: a role that has been open a long time is the one you most need to see, so the list is never bounded by date.

Adding and editing roles

Admins, Delivery Managers and Talent Partners can add new roles using the + Add Role button. Any role can be edited using the action links in the table. When creating a role, select the Functional Area and hire Location — currency is auto-populated from the location and does not need to be entered manually. The Project dropdown on this form lists Active projects only; an existing role already linked to a project that has since moved to Archive still shows it when you edit that role.

The form is split into headed sections: Basics (Project, Role Title, Functional Area, Stage), Ownership (Assign to — shown to Admins and Delivery Managers; a Talent Partner's role is assigned to them automatically — and Hiring Manager), Commercial (Location, Budget per head, Currency) and Headcount. Every required field (marked *) is in these four sections. Priority and Notes sit in Additional details at the bottom, which is collapsed when you add a new role — click it to expand. When you edit a role that already has a Priority or Notes set, it opens automatically so nothing is hidden.

When you add a role, the Headcount section asks for the # of Headcount (how many hires the client wants on this pipeline) plus an Open Date, Target Hire Date (auto-filled as Open + 45 days) and Backfill. Newton creates that many headcount, each with those values — change them one by one afterwards on the role page. A new role starts at any stage except Closed or Cancelled. When you edit a role, the Headcount section just shows its current headcount, with a link to manage them on the role page.

The role page and its headcount

Click any role name to open its role page. It shows the project, stage and Talent Partner, the role's Headcount, and its checklist when it has one. Copy link gives you a link straight to the page.

  • + Add headcount — add one or more headcount, with their own Open / Target dates, Backfill and Notes. Adding headcount to a Closed or Cancelled pipeline reopens it: pick the stage it should go back to (Sourcing by default). That's how to handle a client asking for another hire on a role you have already filled — no need to create a new role.
  • Edit — change a headcount's dates, Backfill or Notes. Clearing a date removes it.
  • Cancel — the client no longer wants that hire. It stays on the page as Cancelled and stops counting toward x/y. If it was the last open headcount, Newton offers to close the pipeline (if something was filled) or cancel it (if nothing was).
  • Restore — undo a cancel, while the pipeline is still open.

A headcount is Filled when a placement is linked to it; the page shows who and when. Headcount are never deleted.

Updating a stage without opening the form

Each row has its own stage dropdown — pick a new stage and it saves immediately, no need to open Edit. This covers every stage except Closed and Cancelled, which still go through the full Edit form since they trigger other changes elsewhere in Newton.

Wherever you change a stage (the dropdown, the Edit form or the mobile app), Newton checks the role's headcount first:

  • Closed is blocked while any headcount is still open — fill or cancel it first.
  • An active stage needs at least one open headcount — add one on the role page.
  • Cancelled also cancels every open headcount on the pipeline. Newton asks you to confirm first. Filled headcount are kept.

Duplicating a role

Use the Duplicate action next to Edit to open the Add Role form pre-filled with the source role's Project, Title, Hiring Manager, Talent Partner(s), Budget, Location, Priority, Functional Area and Notes. If Priority or Notes was carried over, the Additional details section opens so you can check them. Stage resets to Backlog; the Headcount section starts at one headcount opening today (Target Hire Date = today + 45 days). The original role is untouched. Use it for a different pipeline with the same profile (for example another location) — for more hires on the same pipeline, add headcount on its role page instead.

Days Open and the "Roles Open 30+ Days" panel on both dashboards are driven by headcount Open Dates — set them accurately when you add a role or headcount.

Creating a briefing pack

Use the Briefing Packs button in the page header to open the Briefing Pack Library, where you can open, copy or delete a saved pack — or start a new one. See Briefing Packs below.

Viewing a role's history

Use the Timeline action next to Edit to see a role's full stage journey — every stage change, in order, with the date it happened and how long the role spent in that stage before moving on. A move that takes the role forward through the pipeline is shown in green; a move backward (for example, Interview 2+ back to Interview 1) is shown in red; a move onto or off On-hold or Cancelled is shown in amber, since neither is a step forward or back. The Timeline action only appears on roles that have recorded history — roles created before this feature shipped (August 2026) have nothing to show, so the action is hidden on those.

If a role's Open Date is earlier than when it was entered into Newton — or earlier than when it was actually moved into Sourcing — the timeline shows the Open Date as the true start of that stage instead of the later system date, labelled "Role opened." This keeps stage durations honest for a role that's logged into Newton, or moved into Sourcing, after the fact.

Weekly Activity

Admin Delivery Manager Talent Partner

Records weekly pipeline activity against specific roles — Outreach, Responses, Screened, Submitted, Interview 1, Interview 2+, Final Interview, Offers, and Hires. Each entry is tied to a role, a Talent Partner, a year, and a week number.

Filtering

Filter by project using the dropdown, grouped into Active and Archive sections. Talent Partners see only their own entries; Delivery Managers and Admins see all entries for their projects.

The Period dropdown controls how much history is fetched — it defaults to Last 26 weeks, so older entries are not loaded until you widen it. Choose All time to load everything. If a count looks lower than you expect, check this first. The Show dropdown (25 / 50 / 100 / All, default 50) then limits how many of those rows are drawn, without re-fetching. The line under the toolbar always names the period you are viewing.

Adding activity

Use + Add Activity to log a week's numbers for a single role. Select the role, enter the week ending date, and fill in the activity counts. This data feeds directly into the dashboard pipeline panels. The Project dropdown on this form lists Active projects only.

Bulk logging a whole week

Use ⚡ Bulk log week to log every role you can see in one grid, one save, instead of opening the single-role form repeatedly. Pick a week-ending date and the grid loads a row per role, grouped by project; any rows already logged for that week are pre-filled so this is also how you correct a week you've already entered. Only the rows you actually change are saved — untouched rows are left alone. Each row saves against the Talent Partner assigned to that role; a role with no Talent Partner assigned shows as disabled. If one row fails to save, the rest still go through — the failed row stays open and marked so you can retry it.

Placements

Admin Delivery Manager Talent Partner

Records successful hires — candidate name, role, agreed salary, and provisional start date. Each placement fills one headcount on a role.

Filtering

Filter by project — grouped into Active and Archive sections — and by Month, Quarter, or Year using the filter rows below the project dropdown.

The Period dropdown controls how far back placements are fetched, and defaults to Last 52 weeks. Choose All time to load every placement ever recorded. The Month / Quarter / Year buttons still work regardless of the period — picking an earlier month widens the fetch automatically rather than returning nothing. The Show dropdown (25 / 50 / 100 / All, default 50) limits how many rows are drawn without re-fetching, and the line under the toolbar names the period so a narrowed list is never mistaken for the whole list.

Recording a placement

Use + Record Placement to log a hire. Pick the Headcount the hire fills: the list shows the project's open headcount, grouped by role, earliest opened first — headcount with no Open Date come last, marked not opened. The currency field auto-populates from the role's location. The salary field feeds the Actual Spend vs Budget panel on the Project Dashboard, so accuracy here matters. The Project dropdown on this form lists Active projects only.

A role isn't listed when it has no open headcount, or is Backlog, On-hold, Closed or Cancelled. Add headcount on the role page first — that also reopens a Closed role. If someone fills or cancels the headcount while you're on the form, saving tells you to pick another.

Time to Hire is counted from the headcount's Open Date to the Offer Accepted Date. It's blank for a headcount that was never opened.

After you save: if that placement filled the role's last open headcount, Newton offers to close the pipeline. If headcount are still open, it asks which stage the pipeline is at now, so a role left on Offered doesn't show as stuck. On mobile, a message offers Update stage instead.

Editing a placement can move it to a different headcount; the one it leaves becomes open again. If that one is on a Closed or Cancelled role, Newton offers to cancel it.

A placement's provisional start date is what populates the Upcoming Starters panel on the Project Dashboard.

Rejected Offers

Admin Delivery Manager Talent Partner

Logs offers that were not accepted, recording the candidate name, role, and rejection reason. Reason categories are: Salary, Motivations, Counter-offer, Took another opportunity, and Other.

Filtering

Filter by project using the dropdown, grouped into Active and Archive sections.

A Period dropdown is available but defaults to All time, so nothing is hidden unless you choose to narrow it. Note that rejections logged before the Rejection Date field existed have no date, and choosing a bounded period will exclude them — that is why All time is the default. The Show dropdown (25 / 50 / 100 / All, default 50) limits how many rows are drawn.

Recording a rejection

Use + Record Rejection to log a declined offer. Rejection Date is required and defaults to today — change it if you are logging something that happened earlier. This data feeds the Offer Rejection Reasons panel on the Project Dashboard, helping identify trends over time.

That panel is period-scoped by the rejection date. Before this field existed it fell back to the linked role's hire date, which meant any rejection against a role that had not been filled was counted in every period — so historical rejection trends before N-153 should be read with that in mind.

Hiring Plan (CoE projects)

Admin Delivery Manager Talent Partner Leadership

A month-by-month hiring roadmap for Centre of Excellence (CoE) projects. Each planned role appears as a row on a Gantt-style timeline showing its Recruitment (blue), Notice (pink), and Onboarding (green) phases week by week. The page only shows projects marked as CoE in the project form. Admins and Delivery Managers can build and edit the plan; Talent Partners and Leadership have a read-only view.

Building the plan

Use + Add Planned Role and enter a role title and planned open date — the phases fill in automatically from the standard assumptions. Leave the phase-length fields blank to use the defaults, or enter a number of weeks to override any phase for that role. The Target Hire Date is calculated automatically as the open date plus the recruitment phase.

Capacity and filtering

The rows above the timeline show how many roles are in each phase every week — use these to spot capacity peaks. Assign a Talent Partner to each row and use the Talent Partner dropdown to view one person's workload at a time.

Linking to live headcount

Each planned role tracks one hire — a headcount on a live role. Use Link to connect the row to a headcount: the list shows headcount not already on another plan row, grouped by role, with open ones first and filled ones marked filled. Open headcount on roles that are Closed, Cancelled or On-hold aren't listed; filled headcount are, whatever the role's stage, so a plan row can point at a hire that has already completed. Use Create Headcount to add one: either to an existing role, or by opening a pre-filled Add Role form — the new headcount is linked to the row automatically. The Open and Target Hire dates come from the plan and can be changed; clear the Open Date for a hire that is planned but not yet active. Linked rows (marked 🔗) show a thin bar along the bottom of the timeline tracking actual progress against the plan — from the headcount's open date to the offer accepted date, then to the placement's start date.

Forecast vs Planned Hires

The table below the timeline compares monthly hire numbers. Forecasted is calculated from the target hire dates on the timeline; the planned column is entered by the Delivery Manager. The variance column highlights months where the plan and forecast diverge, supporting conversations about scope and customer expectations.

Report Library

Admin Delivery Manager Talent Partner

The Report Library is where you find, open and start client-facing reports. Clicking Report Library in the navigation brings you here first — you reach the report builder itself only by opening an existing report or starting a new one.

Finding a report

Reports are grouped by client, with a Company-wide group at the top for reports not tied to a project. Use the Client filter to narrow the list. What you see depends on your role: Admins see every saved report; Delivery Managers see every company-wide report plus reports for their assigned projects; Talent Partners see reports for their assigned projects. You'll always see a report you created yourself, even if you're no longer assigned to its project.

Opening, copying and deleting

Click Open to load a report into the builder. Click Copy to create your own duplicate — named "<title> (copy)" — which opens straight into the builder so you can adjust it without affecting the original. Delete is only shown to the report's owner or an Admin.

Starting a new report

Click + New Report in the Library header to open a blank builder.

Building a report

Use the left-hand configuration panel to set the Scope (project or company), select a Project (if project scope — grouped into Active and Archive sections), choose a Period, and set the KPI Period (Month, Quarter, or Year). Then toggle the panels you want to include from the module list.

Canvas and ordering

Selected panels appear on the right-hand canvas. Drag and drop panels using the handle on the left of each block to reorder them. The order you set here is the order they appear in the PDF export.

Saving a report

Click Save to persist your current configuration (scope, project, period, panel selection, and order) to the Library. Click ← Back to Library at any time to return there.

Exporting to PDF

Click Export PDF to open the browser print dialog. Set Destination to Save as PDF, ensure Background graphics is ticked, and untick Headers and footers.

Each panel in the report builder corresponds to a section of the Project Dashboard. If a panel has no data for the selected period, it renders as empty — review your Period setting if panels appear blank.

Briefing Packs

Admin Delivery Manager Talent Partner

A briefing pack is a Momentum-branded document you send to a candidate about a specific role — the client, the opportunity, the process, and who to talk to. You write the content yourself, save it to a library so it can be picked up and amended later, and export it as a PDF.

The Briefing Pack Library

Go to Roles and click Briefing Packs in the page header. The library lists every pack you can see, grouped by client, with the pack name, the role, its location and who owns it. Use the Client filter above the table to narrow it to one customer.

What you see depends on your role: a Talent Partner sees the packs they created; a Delivery Manager sees their own plus every pack on a project assigned to them; Admin and Leadership see all of them. The client a pack sits under comes from the project it was built against, so packs for the same customer stay together even where the client name was typed differently on each one.

Each row has three actions. Open loads the pack into the builder. Copy duplicates it as "<pack name> (copy)", makes you the owner and opens the copy straight away — the original is untouched, which is how you reuse someone else's pack. Delete appears only on packs you own (admins see it on every pack) and cannot be undone.

Starting a pack

Click + Briefing Pack in the library header. The builder opens with a title page and a closing page already in place — these two always exist and always sit first and last.

Setting up the pack

In the left-hand panel, choose the Project and Role. The client name, role title, location and your name and email fill in automatically from the role record. Every one of those fields stays editable, so change anything that should read differently on the pack. Set the Pack Title and the Cover Date, and check the closing-page contact details at the bottom of the panel.

The client logo

Upload the client's logo under Client Logo. It is saved against the project, not the pack, so you only do this once per client — every future pack for that client picks it up automatically. PNG, JPG or SVG, under 150 KB.

Use a roughly square version of the logo, in colour or dark — it sits in a small white tile on the navy cover, so a wide banner logo will look small and a white-on-transparent logo will disappear.

Adding pages

Add pages from the bottom of the left-hand panel:

  • Content Section — a heading and a rich-text body. The toolbar gives you bold, italic, underline, bullet and numbered lists, headings, a Table and a Callout block (a highlighted panel, useful for key facts like salary, location and reporting line).
  • Divider — a full-page branded break carrying a heading. Dividers are numbered automatically in the order they appear, so moving one renumbers the rest for you.

Drag pages by the handle on the left to reorder them. The title and closing pages cannot be moved or removed.

Saving and going back

Click Save to store the pack, then ← Back to Library to return to the list. Saved packs stay in the library for you to reopen, copy or delete later; only the person who created a pack, or an admin, can delete it.

Exporting to PDF

Click Preview to check the pack on screen, then Export PDF. Set Destination to Save as PDF, tick Background graphics and untick Headers and footers. A contents page is generated automatically after the cover, and a Confidential line appears on every page.

Briefing packs are the only portrait export in Newton — every other export is landscape. You do not need to change anything in the print dialog for this; it is handled for you.

How pages come out

Short sections share a page, each in its own bordered tile. A section that will not fit in the space left starts on the next page rather than being split across two. A section longer than a whole page will split — if you would rather control where the break falls, divide it into two sections.

If the cover and closing pages come out without the swirl graphic, check that Background graphics is ticked in the print dialog, then export once more.

Config Panel

Admin

The Config Panel is visible to Admins only and provides two management functions within the Reporting module. Currencies are no longer managed here — they are auto-derived from the role's Location field.

Departments

Manage the list of departments used when categorising roles and projects across the system. Departments are scoped per customer — add or remove them here as your project structures change.

Delete Records

Permanently delete records from any SharePoint list. Select the list and the specific record, then confirm the deletion. This cannot be undone from within Newton — use SharePoint's recycle bin if you need to recover a deleted item.

User and access management has moved to the Newton OS Admin area, accessible via the Admin link on the Newton home screen.

AI Agents

Admin Delivery Manager Talent Partner

Momentum Global’s AI agents run in Microsoft 365 Copilot and support each stage of our recruitment workflow — from preparing a role intake through to the final hiring decision. Each agent has one defined job. Use the right agent at the right stage, review its output before moving on, and remember that you stay accountable for the work.

Installing an agent

Open the agent’s section below and select Add to Teams. The link opens Microsoft 365 Copilot Chat — sign in with your Momentum Global account if prompted, then confirm to add the agent to your profile. Add each agent once; it then stays available to you.

Accessing your agents

Once added, your agents appear in Microsoft 365 Copilot Chat and in Teams. Open the agent, then attach or paste the inputs listed in its Usage flow before asking it to produce anything.

Role checklists can link straight to an agent’s entry in this guide — each agent has its own link (for example user-guide.html#agent-nelson), so a checklist step like “Build the Campaign Brief” can point at Nelson.

Function

Brunel helps Talent Partners turn an agreed interview-process discussion into a clear, structured Interview Process Guide for Hiring Managers and interview panels.

It defines what each stage is designed to assess, who owns it, what evidence should be gathered and how the stages work together.

The aim is to create a consistent, efficient and evidence-based process rather than a series of loosely connected interviews.

Key features

  • Creates an end-to-end Interview Process Guide
  • Defines each interview stage, purpose, interviewer, format and duration
  • Maps role criteria to the appropriate assessment stage
  • Defines the expected level or behaviour for each criterion
  • Creates evidence-based interview questions and follow-up probes
  • Uses CEO questioning where appropriate — Context, Example, Outcome
  • Supports technical tests, case studies and practical assessments where agreed
  • Builds the Talent Partner screening framework from the wider process
  • Creates an assessment coverage matrix to identify gaps or duplication
  • Defines the final wrap-up and decision process
  • Flags unresolved information rather than inventing answers

Usage flow

Provide Brunel with the Interview Process Discussion transcript. This can come from:

  • The role intake/kick-off meeting, where sufficient time was spent agreeing the interview process; or
  • A separate Interview Process Design meeting.

Also provide, where available:

  1. Approved Campaign Brief
  2. Screening Document / Assessment Guide
  3. Job Description

Brunel will then produce:

  1. Interview process purpose
  2. Process-at-a-glance
  3. Stage-by-stage interview guides
  4. Competency expectations and interview questions
  5. Technical/practical assessment guidance where required
  6. Talent Partner screening guide
  7. Assessment coverage check
  8. Wrap-up and decision process
  9. Decisions Required for anything still unresolved

The Talent Partner reviews any unresolved decisions with the Hiring Manager before the process is finalised and shared.

Outcome

A credible, Hiring Manager-ready Interview Process Guide where every stage has a clear purpose and every essential criterion is intentionally assessed.

Interviewers know what they own, candidates experience less repetitive interviewing, and the final hiring decision is supported by consistent evidence gathered throughout the process.

Using Agents Well

Admin Delivery Manager Talent Partner
The agents are here to improve the quality, consistency and efficiency of our work — not to replace Talent Partner judgement. The strongest results come when good process, strong inputs and human expertise work together.

Augment, don’t replace

  • Human judgement stays central: Agents can research, structure, challenge and draft, but the Talent Partner remains accountable for the quality of the work and the decisions made from it.
  • Follow the process: The agents are designed to support our recruitment methodology, not create shortcuts around it.
  • Relationships still matter: Hiring Manager alignment, candidate engagement, challenge and influence remain fundamentally human responsibilities.
  • Treat outputs as a strong first draft: Review, challenge, and refine before sharing anything externally.

Input quality determines output quality

  • Better inputs create better outputs: Agents can only work effectively with the information they are given.
  • Use the right source material: Provide current JDs, transcripts, approved briefs, assessment guides and candidate information wherever required.
  • Do the work upstream: A weak intake cannot be rescued by a strong prompt. Thorough scoping and clear Hiring Manager alignment remain essential.
  • Correct mistakes early: Review outputs between stages rather than allowing an incorrect assumption to flow through the rest of the workflow.

Use the right agent for the right job

  • Each agent has a defined purpose and should stay within its area of expertise.
  • Avoid asking one agent to replicate work that another agent is specifically designed to perform.
  • Where agents hand work to one another, make sure the upstream output has been reviewed and agreed first.
  • Some agents are still being tested for specific use cases and may not yet be appropriate for every client or delivery model.

Challenge the output

  • AI confidence is not evidence: A well-written answer can still be wrong, incomplete or based on a poor interpretation.
  • Check that requirements, candidate evidence, market information and recommendations reflect what was actually agreed or provided.
  • If something feels generic, over-engineered or unsupported, challenge it and ask the agent to refine the output.
  • Never allow an agent to manufacture missing information simply to complete a document.

Protect fairness & candidate experience

  • Assessment criteria should remain relevant to success in the role and applied consistently.
  • Watch for assumptions, unnecessary requirements or language that could introduce bias.
  • Use agents to reduce repetitive interviewing and improve preparation — not to remove meaningful human interaction from the process.
  • Hiring decisions remain the responsibility of the interview team.

We’re still learning

  • Expect iteration: These agents will continue to evolve as we learn what works in real recruitment campaigns.
  • Feedback matters: Share examples of strong outputs, weak outputs and unexpected behaviour.
  • Keep improving the prompts: If an agent repeatedly requires the same correction, we should improve the agent rather than rely on every TP remembering the workaround.
  • Build collectively: The goal is a shared toolkit that makes every Talent Partner more effective while protecting the quality of our methodology.
